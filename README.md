# SkySend · комплект для разработки нового сайта

Подготовлен 10.09.2026 на основе [skysend.ru](https://skysend.ru/) с визуальным референсом [DJI](https://www.dji.com/). В комплект входят аудит, новая структура, готовые тексты, исходные и подготовленные ассеты, макеты, спецификация анимаций и план реализации. Сам сайт должна реализовать следующая модель.

## Что использовать в реализации

| Данные | Назначение |
|---|---|
| [site-content.json](data/site-content.json) | Главная и 7 страниц ПО, 30 секций с текстом, источником, визуалом, мобильной версией и анимацией |
| [secondary-content.json](data/secondary-content.json) | Партнёрские и служебные страницы, готовые тексты и состояния |
| [equipment-content.json](data/equipment-content.json) | Две реальные модели терминалов и их исходные характеристики |
| [utility-content.json](data/utility-content.json) | Индексы ПО и оборудования, каталог провайдеров, загрузки и страница правил |
| [navigation.json](data/navigation.json) | Меню, действия, единые контакты и внешние кабинеты |
| [section-assets.json](data/section-assets.json) | Связь смыслового ID с конкретным файлом и alt-текстом |
| [assets-manifest.json](data/assets-manifest.json) / [CSV](data/assets-manifest.csv) | Происхождение, размеры, SHA256, MIME и пригодность ассетов |
| [provider-wall-selection.json](data/provider-wall-selection.json) | Подборка 16 настоящих логотипов для главной |
| [providers-source.json](data/providers-source.json) | Снимок открытого каталога: 600 строк в 13 категориях |
| [download-catalog.json](data/download-catalog.json) | Отобранные загрузки, ссылки, результаты проверок и состояния ошибок |
| [migration-map.csv](data/migration-map.csv) | Решение для каждого старого URL: перенос, объединение или удаление |
| [motion-spec.json](data/motion-spec.json) | Триггеры, тайминги, mobile и reduced motion |
| [design-tokens.css](assets/design-tokens.css) | Цвета, шрифты, интервалы, размеры и базовые правила движения |

`assets/originals/` сохраняет исходные файлы. Для сайта применяются только разрешённые записи реестра и явные привязки. `assets/brand/`, `assets/diagrams/`, `assets/icons/`, `assets/ready/` содержат подготовленные файлы. Inter и лицензия находятся в `assets/fonts/`.

`evidence/` и `assets/source-with-review/` служат исследовательским архивом. В нём намеренно сохранены и материалы, которые были исключены. Не копировать весь репозиторий в публичную папку сайта.

## Зафиксированные решения

- «Программы» переименовано в «ПО». Акции и промо отсутствуют в новой структуре и активных текстах.
- Предметные изображения: реальные терминалы, экраны ПО, логотипы каталога и схемы, основанные на исходном описании.
- «Более 5 000» сохранено из старого сайта. Снимок открытого каталога содержит 600 записей и не является подтверждением общего количества или текущей доступности каждой оплаты.
- Адреса и некоторые контакты в исходнике расходятся. В базовом интерфейсе используются общие каналы, а для адреса задан текст «Адрес офиса уточняйте по телефону».
- Внешний вход и регистрация имеют сетевые проблемы при проверке. Для `/connect/` задан рабочий путь через поддержку; новая форма пароля не требуется.
- Цена и наличие оборудования не выводятся без текущих данных. Характеристики и пометки о б/у компонентах сохраняются.

## Проверка комплекта

`python tools/validate_handoff.py` проверяет JSON/SVG, наличие привязанных файлов, контрольные суммы и первичные текстовые ограничения. Итог проверки сохраняется в [validation-report.json](data/validation-report.json).

Для чтения, просмотра макетов и начала разработки установка зависимостей не требуется. [Контракты контентных компонентов](docs/08-content-components.md) определяют сборку списков и схем из готовых данных. Скрипты в `tools/` и `scripts/` сохраняют историю исследования и сборку материалов; они не являются frontend-приложением. `scripts/build-audit-deliverables.py` отражает ранний этап исследования и перезаписывает вручную проверенные результаты; не запускать его при обычной разработке. Финальные JSON/CSV и документы являются источником истины.
