# SkySend: фронтенд, дизайн-токены и анимации

Дата спецификации: 10.09.2026. Это договорённости для разработки нового публичного сайта. Рабочий сайт, платёжные операции, личный кабинет и серверные интеграции в этом комплекте не реализованы.

## 1. Как применять референс DJI

На [главной DJI](https://www.dji.com/) объектом каждого продуктового блока служит конкретный продукт, а переход ведёт к его подробностям. На [DJI Flip](https://www.dji.com/flip) и [Osmo Action 6](https://www.dji.com/osmo-action-6) есть предметное изображение, название продукта, характеристики и отдельные ссылки на спецификации, загрузки и поддержку. Для SkySend принимаем эту логику: факт, реальный интерфейс или оборудование, затем уместное действие. Коммерческие предложения и промо DJI не переносим.

Размеры, цвета, длительности и easing ниже являются проектными решениями SkySend. Они не извлечены из CSS DJI и не заявлены как результаты измерения его анимаций. Скриншоты DJI в `evidence/` служат визуальным ориентиром, их изображения и видеоматериалы не входят в публикуемые ассеты SkySend.

Три композиционных правила:

1. В секции с числом провайдеров видны настоящие логотипы провайдеров. В секции о настройке терминала виден соответствующий экран терминала. Изображение общего назначения вместо этого не подходит.
2. Используем белые и светло-серые поверхности, один тёмный предметный блок при необходимости, крупный объект без нарочитого свечения. Цвет логотипов и UI сохраняется.
3. Ритм меняется по содержанию: широкий предметный блок, разделённая композиция, плотный список, техническая таблица. Не превращаем сайт в сетку одинаковых карточек.

## 2. Архитектура и границы

Публичные страницы должны отдавать содержательный HTML: статическая генерация либо SSR на стеке, который использует будущий разработчик. Смена работающей CMS или framework ради этого дизайна не требуется. Если исходный проект не содержит приложения, уместен лёгкий статический генератор с отдельными интерактивными компонентами. Версия и конкретный framework не являются требованием данного плана.

В HTML присутствуют H1, основные тексты, ссылки, изображения и списки. JavaScript обслуживает меню, просмотр скриншотов и описанные анимации. Пользователь читает сайт и переходит по ссылкам при отключённом JS. Для меню нужен обычный доступный резервный список навигации, для просмотра скриншота достаточно ссылки на изображение.

Регистрация и вход ведут на существующие адреса, зафиксированные аудитом. Страница `/connect/` объясняет переход и показывает проверенные контакты. Не создаём локальную форму регистрации, обработчик заявок, API оплаты, «онлайн-баланс», вымышленные успешные платежи или имитацию кабинета. Недоступность внешнего сервиса не подменяем фальшивым состоянием «Заявка отправлена».

Содержимое хранится отдельно от шаблонов. Использовать уже переданный `data/site-content.json`: страница содержит `path`, `title`, `template`, `source_url`, `sections`; секция содержит `id`, `title`, `paragraphs`, `bullets`, `cta`, `media`, `source_urls`, `visual`, `mobile`, `motion`, `caption`, `copy_status`. `media` связывается с `data/section-assets.json`, `motion` с alias в `data/motion-spec.json`. Дополнительные страницы брать из соответствующего файла контента этого комплекта. Публичные title/description/canonical формирует шаблон метаданных по содержимому страницы; исходные URL и редакторский статус не выводятся пользователю. Это контракт данных, а не требование внедрить новую CMS. Источник окончательных текстов и порядка блоков находится в контентной спецификации комплекта; в шаблонах не писать новый рекламный текст.

## 3. Токены и типографика

Готовый источник значений: [`assets/design-tokens.css`](../assets/design-tokens.css). Не добавлять альтернативные значения для одного и того же системного отступа в отдельных страницах.

Шрифт: локальный [`InterVariable.woff2`](../assets/fonts/InterVariable.woff2), лицензия [`OFL.txt`](../assets/fonts/OFL.txt). В файле есть латиница и кириллица; основной текст 400, подписи навигации 600, заголовки 600. Нужна только прямая версия шрифта. Не загружать библиотеку иконок ради нескольких стрелок.

```css
@font-face {
  font-family: "Inter";
  src: url("/assets/fonts/InterVariable.woff2") format("woff2");
  font-style: normal;
  font-weight: 100 900;
  font-display: swap;
}
```

Этот URL является путём будущей публикации; при сборке с хешированием адрес заменяет сборщик. Fallback: Arial, Helvetica Neue, Helvetica, sans-serif. Проверять переносы с загруженным Inter и с fallback. Не подбирать `size-adjust` на глаз: если добавляется метрическая коррекция, измерить её по этим двум шрифтам.

| Роль | 320–767 px | 768–1199 px | От 1200 px | Line-height / вес |
|---|---:|---:|---:|---|
| H1 | 36 px | 44 px | 56 px | 1.10 / 600 |
| H2 | 30 px | 36 px | 40 px | 1.16 / 600 |
| H3 | 22 px | 24 px | 28 px | 1.25 / 600 |
| Лид | 18 px | 18 px | 20 px | 1.50 / 400 |
| Основной текст | 16 px | 16 px | 16 px | 1.55 / 400 |
| Подпись, метаданные | 14 px | 14 px | 14 px | 1.45 / 400 |
| Навигация | 14 px | 14 px | 14 px | 1.45 / 600 |

Таблица соответствует значениям `rem` при корневом размере браузера 16 px. Корневой размер не фиксировать в пикселях; масштаб текста пользователя должен сохраняться. H1 на узком экране может занимать четыре строки, обрезать его или уменьшать весь экран через transform нельзя. Отрицательный трекинг только заголовков: `-0.02em`. Сплошной текст ограничить 42 rem, короткие вводные абзацы 32–36 rem. Длинные русские слова переносятся по нормальному текстовому потоку; принудительные `<br>` в контенте запрещены. Для URL и технических идентификаторов допускается `overflow-wrap: anywhere`.

Цвета текста: основной `#111315`, вторичный `#5F6368`, на тёмном фоне белый и `#BCC2C8`. Ссылки `#0066B3`, hover `#004D87`. Белый и `#F4F5F6` являются основными фонами. Линия `#D8DCE0` отделяет области; если граница единственная подсказка о существовании элемента управления, использовать контрастную `#757B80`. Тёмный фон `#111315`. Синий не закрашивает большие декоративные области.

Небольшие подписи не уводить в бледный серый. Текст поверх картинки применять только при заранее проверенной читаемости на всех кадрированиях. Предпочтительнее отдельная текстовая область. Числа, сроки, названия и операционные системы не дописывать по визуальному впечатлению от скриншота.

## 4. Сетка и адаптация

| Параметр | 320–767 px | 768–1199 px | От 1200 px |
|---|---:|---:|---:|
| Колонки | 4 | 8 | 12 |
| Боковой отступ | 20 px | 32 px | 48 px |
| Межколонник | 16 px | 24 px | 24 px |
| Вертикальный отступ секции | 48 px | 64 px | 80 px |
| Шапка | 64 px | 64 px | 72 px |
| Навигация | Меню | Меню | Ссылки |

Контейнер: `width: min(100% - 2 * gutter, 1280px)`; центрировать. Фон блока может занимать всю ширину экрана, его текст и средства управления привязаны к контейнеру. На 1440 px ширина контейнера составляет 1280 px; на 1920 px объекты не растягиваются до размеров случайного билборда.

Главная:

- `#hero`: на desktop текст 5 колонок, 1 колонка разделения, предметный визуал 6. Первый экран при 1440×900 занимает ориентировочно 560–680 px вместе с внутренними отступами; это ориентир композиции, а не фиксированная высота. Не устанавливать `height: 100vh`. На мобильном: H1, пояснение, CTA, изображение. Минимальная высота не должна создавать пустую область.
- `#providers`: текст рядом с или над единой композицией логотипов. Логотипы не являются одинаковыми карточками. На мобильном использовать специально собранный компактный вариант, в котором читаются ключевые бренды; не сжимать широкий баннер до неразличимых пятен.
- `#terminal-software`: крупный настоящий экран. `object-fit: contain`, пропорция исходника сохраняется; не обрезать управляющие элементы и название ПО ради заполнения площади.
- `#customization`: визуал показывает изменение интерфейса/оформления, которое действительно подтверждено исходником. Если в наличии один подтверждённый пример, показываем один, без выдуманного переключателя «до/после».
- `#commerce`: объясняющая композиция только из подтверждённых способов и интерфейсов. Изображение не имитирует работающую платёжную форму.
- `#partners`: список направлений с разными по объёму пояснениями и прямыми ссылками. Не принуждать пункты к одинаковой высоте декоративными пустотами.
- `#equipment`: предметные изображения на нейтральном фоне. Не растягивать маленькие JPEG. Для карточки товара использовать `contain`; для согласованного крупного фото допускается `cover` с прописанным focal point.
- `#support`: плотный, хорошо читаемый блок контактов/ссылок. Никакого героя с оператором из стока.

Детальные страницы ПО: заголовок и описание, крупный реальный экран, подтверждённые функции, загрузки/документация, контакты или переход к подключению. Важную функцию не прятать в hover. Страницы партнёров используют введение, предметное подтверждение, условия и последовательность подключения из исходного контента. Служебные страницы, архив новостей и контакты получают более плотную редакционную вёрстку без полноэкранного баннера.

На мобильном DOM-порядок совпадает с чтением: заголовок → текст → изображение → связанные подробности. Если CTA относится к введению, он остаётся в текстовой группе до изображения. Не переставлять элементы только визуально, нарушая порядок Tab. У списков оборудования и ПО 1 колонка на телефоне, 2 на планшете; desktop композиция выбирается по изображению, а не по автоматическому повторению карточек.

Изолированные технические таблицы могут иметь свой горизонтальный scroll с явной подписью; вся страница не должна прокручиваться горизонтально. Sticky-шапка непрозрачная, без blur. При увеличении текста или недостаточной высоте viewport она становится обычной статической, чтобы не перекрывать содержимое.

| `ManualGallery` | Только подготовленные реальные кадры, текстовые названия, alt | Ручное переключение; без автоплея и зацикливания; «Назад»/«Далее», подпись «Кадр N из M»; на границах кнопка имеет `aria-disabled="true"` и не меняет кадр, оставаясь доступной фокусу; смена подписи объявляется через polite live-region |
| `PartnerList` | Название направления, описание, ссылка | Семантический список; не кликабельный `div`; доступная подпись ссылки понятна вне контекста |
| `EquipmentItem` | Название, реальное фото, проверенный URL, известные характеристики | Не добавлять цену, наличие, корзину или «Купить», если этих данных/действий нет в согласованном контенте |

| `ContactBlock` | Телефон/email/адрес из источника | `tel:` и `mailto:`, перенос длинных адресов; карта только по потребности и без загрузки тяжёлого iframe до действия пользователя |
| `ActionLink` | `label`, `href`, internal/external/download | Навигация через `<a>`; программное действие через `<button>`; внешний кабинет не открывается в iframe |
| `Breadcrumbs` | Иерархия из реального route-tree | `<nav aria-label="Хлебные крошки">`, список, последний пункт обозначает текущую страницу |
| `NotFound` | H1 «Страница не найдена», реальные ссылки | Настоящий HTTP 404; на удалённых промо отдельный HTTP 410; не «успешная» страница с кодом 200 |

Общие состояния интерактивных элементов: default, hover только для точного указателя, active, focus-visible. Focus: контур 3 px, offset 3 px; на тёмном фоне `#82C4FF`. Элемент имеет активную область не меньше 44×44 CSS px, у основных CTA высота 48 px. Это принятый в проекте размер выше базового порога WCAG 2.2; WCAG 2.5.8 описывает порог 24×24 и отдельные исключения, а не универсальное требование 44 px. [W3C: Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

Нельзя обозначать ошибку или доступность только цветом. На текущем публичном сайте новые формы не предусмотрены; состояния validation/submitting/success не создаём без реального серверного контракта.

## 6. Семантика и доступность

`<html lang="ru">`, skip-link «Перейти к содержимому», один `<main>` и один H1 на страницу. Секции называют H2, внутренние подразделы H3. Для изображений использовать `<figure>` и подпись там, где подпись объясняет фактический источник или назначение. Текст внутри скриншота не является заменой HTML-описания функции.

Мобильное меню выбрано как модальная панель на ширинах меньше 1200 px. Название кнопки «Меню»/«Закрыть меню», `aria-expanded`, `aria-controls`. При открытии фокус попадает в меню, фон недоступен для взаимодействия; Escape и кнопка закрывают панель, фокус возвращается на исходную кнопку. Если пользователь выбрал ссылку, продолжает работать обычная навигация. При переходе к desktop открытую панель закрыть, снять `inert` и scroll-lock. Такой порядок соответствует паттерну [W3C Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

Предпочтение уменьшенного движения считывается через `matchMedia('(prefers-reduced-motion: reduce)')` и CSS media query. Изменение настройки во время сеанса завершает активные эффекты в конечном состоянии. Принцип настройки описан в [MDN: prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion); конкретное упрощение эффектов ниже задано проектом.

## 7. Каталог анимаций

Машиночитаемая спецификация: [`data/motion-spec.json`](../data/motion-spec.json). Идентификаторы нужны для реализации и QA, в интерфейсе сайта их не показывать. Поле `motion` из `data/site-content.json` сопоставляется так: `none` → M00; `section-reveal` → M01; `gallery-change` → M05; `process-step` → M02; `link-feedback` → M03. Для первого экрана любой страницы, включая секцию `overview`, действует приоритетный override M00, даже если в контенте задан `section-reveal`.

| ID | Где применяется | Trigger / свойства | Desktop | Mobile/tablet | Reduced motion |
|---|---|---|---|---|---|
| M00 | `#hero`, `#providers`, `#support`; первый экран внутренних страниц | Первый HTML-render | Статично, 0 ms | Статично | Статично |
| M01 | `#terminal-software`, `#equipment`; внутренние секции с alias `section-reveal` ниже первого экрана | Однократный вход: IO threshold .15, rootMargin `0px 0px -48px 0px` | opacity 0→1, Y 16→0 px; 420 ms; enter | Только opacity, 220 ms | Всё видно сразу |
| M02 | `#commerce` | Однократный вход трёхшаговой схемы | Только opacity; 420 ms и задержки 0/60/120 ms | Вся вертикальная схема, opacity 220 ms | Всё видно сразу |
| M03 | Ссылки, кнопки | Hover / focus / active | Цвета 160 ms; feedback | active без задержки | Без transition |
| M04 | Мобильное меню | Нажатие / Escape | Не используется | opacity + Y −8→0 px, вход 240 ms, выход 160 ms | Открытие/закрытие сразу |
| M05 | Просмотр скриншота, `#customization` | Явное открытие/закрытие; ручная смена подготовленного кадра | Только opacity 220 ms | Такой же fade | Сразу |
| M06 | Шапка | Верхний sentinel ушёл за экран | Граница/лёгкая тень 160 ms | Только граница | Сразу |
| M07 | Якоря и skip-link | Ссылка | Нативный переход 0 ms | То же | То же |

`enter = cubic-bezier(0.22, 1, 0.36, 1)`, `feedback = cubic-bezier(0.2, 0, 0, 1)`, `exit = cubic-bezier(0.4, 0, 1, 1)`. M04 закрывается с exit, остальные UI fade используют feedback. Не использовать spring, overshoot и bounce. Токен media 560 ms зарезервирован как верхний предел для возможного предметного перехода, но отдельной сцены на 560 ms в первой версии нет.

M01 не оборачивает целую высокую страницу: observer работает на конкретной группе текста/изображения. До успешной настройки наблюдателя всё видно. Первому экрану не назначается начальная `opacity: 0`. Фокусируемые элементы также не скрываются ради reveal. После однократного появления наблюдение снимается. Возврат браузером, `bfcache`, загрузка страницы по hash и быстрый скролл не повторяют эффекты и не оставляют контент невидимым.

M02 показывает порядок «справочник → заказ → оплата» в объясняющей схеме. Это не индикатор выполнения платежа. Логотипы провайдеров остаются статичными. M05 на основном варианте `customization` означает увеличение цельного исходного изображения; ручная смена кадров появляется только при наличии отдельных подготовленных кадров. Перелистывание не повторяется автоматически, скрытые кадры не попадают в доступное дерево и Tab-порядок. Рамка резервируется по крупнейшему из согласованных кадров, чтобы смена не двигала текст страницы.

Не анимировать `height`, `width`, `top`, `left` всей секции на каждом кадре. Не назначать `will-change` всем элементам постоянно; использовать точечно на время эффекта. Не подключать отдельный animation-framework для этого небольшого набора: CSS и IntersectionObserver достаточно. Не добавлять parallax, pinned-сцены, счётчики от нуля, бегущие провайдеры, WebGL, фоновые частицы, автопрокрутку или автоматическое видео.

### Контракт загрузок

Источник публичного перечня: [`data/download-catalog.json`](../data/download-catalog.json), только массив `items`. В комплекте 66 отобранных записей из 122 исходных; 56 исключённых записей находятся в `excluded_records` только для аудита и не публикуются. Группы и якоря: `terminal`, `rma`, `rma-android`, `xml`, `pos`, `system-documents`, `other`. Исходное название хранится без изменений в `source_title`, читаемое название строки в `display_title`; прямой URL исходника в `direct_file_url`, фактическая цель ссылки в `target_url`. Не путать ссылку магазина приложений с бинарным файлом.

Проверены HEAD-запросами 11 ключевых целей. Десять ответили 200; у карточки РМА Android в Google Play получен 404, подтверждённый GET без чтения тела. Это результат проверки 10.09.2026 из окружения аудита, а не обещание постоянной доступности. У 53 остальных записей статус `source_link_unverified`; содержимое файлов не проверялось. Ответ HEAD 200 не подтверждает корректность программы или актуальность документа.

Для РМА Linux установщик имеет исходную ссылку, но у инструкции «Установка и эксплуатация РМА Linux» ссылка в источнике отсутствует. Строка выводит: «Инструкция для Linux недоступна на сайте. Обратитесь в поддержку.» Ссылка ведёт на `/support/`. Нельзя угадывать адрес инструкции по Windows-аналогу. Для Google Play текущий fallback: «Приложение недоступно по ссылке Google Play. Обратитесь в поддержку.» Исходный FTP-адрес инструкции сервисного режима остаётся в аудите; для обычного браузера используется fallback поддержки, а не придуманная HTTPS-ссылка.

Повторная сборка реестра: `python scripts/build-download-catalog.py`. Она сохраняет зафиксированные проверки для неизменённых URL. `--check-key-links` повторяет только проверки ключевых ссылок без загрузки или исполнения установщиков и документов. Реестр отфильтрован по исходным названиям/URL; это не проверка содержимого всех PDF. Перед публикацией проверять ссылки и содержимое тех документов, которые используются как актуальные правила или инструкции.

## 8. Изображения и производительность

Все цифры ниже являются бюджетами будущего сайта, а не результатами измерения текущего skysend.ru. Считаем переданные по сети bytes после Brotli/gzip для HTML/CSS/JS; для уже сжатых медиа считаем фактический размер файла. Измеряем холодную загрузку без расширений браузера.

| Ресурс / проверка | Бюджет |
|---|---:|
| Изображение первого экрана, вариант mobile | ≤220 KiB |
| Изображение первого экрана, вариант desktop | ≤450 KiB |
| Изображение обычной секции | ≤180 KiB mobile / ≤300 KiB desktop |
| Малое фото оборудования | ≤80 KiB |
| SVG-иконка интерфейса | ≤3 KiB, без сторонних шрифтов и raster-вставок |
| Один локальный WOFF2 | ≤350 KiB; включённый Inter около 344 KiB |
| HTML на страницу | ≤45 KiB |
| CSS для первоначального рендера | ≤45 KiB |
| JS первоначальной страницы | ≤120 KiB; цель ≤60 KiB при статической генерации |
| Передача до готовности первого экрана | ≤900 KiB mobile / ≤1.2 MiB desktop |
| Полная главная после прокрутки до конца | ≤2.5 MiB mobile / ≤4 MiB desktop, без открытых по запросу оригиналов |

Для превью интерфейса использовать WebP высокого качества, AVIF только после визуального сравнения тонкого текста. Оригинал PNG/JPEG оставить источником и, если уместно, открыть по запросу. SVG для логотипа или иконки использовать только если он настоящий вектор, не трассировка пиксельного изображения с искажёнными буквами. Не увеличивать разрешение исходников с помощью генерации и не дорисовывать надписи.

У каждого `<img>` прописать `width`, `height`, корректные `alt`, `srcset` и `sizes` под фактическую сетку. `picture` даёт разное кадрирование mobile/desktop только там, где созданы два согласованных ассета. Для LCP-картинки `loading="eager"` и `fetchpriority="high"`, для контента ниже первого экрана `loading="lazy"` и `decoding="async"`. Резервировать место по aspect-ratio. Атрибуты изображения и правила responsive-кандидатов описаны в [MDN: img](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img); раннее обнаружение LCP-ресурса и приоритет загрузки объяснены в [web.dev: Optimize LCP](https://web.dev/articles/optimize-lcp).

Кандидаты экспортов: 480/768/1280 px для обычной растровой композиции, 1600/1920 px только при достаточном исходнике. Размер экспортов не обязан превышать оригинал. Если исходник мал, уменьшаем область показа или выбираем другую проверенную композицию, сохраняя факт блока. Изображения ниже первого экрана не preload. Первую картинку обнаруживает HTML, не CSS после загрузки JS. Шрифт загружается локально с `swap`; не делать несколько preload на неподтверждённые font subsets.

Картинки и файлы с хешированными именами допускают долгий immutable-cache; HTML переоценивается при обновлении. Не назначать immutable изменяемому `index.html`. Скрипты аналитики и виджеты допустимы только после проверки их необходимости; проект не требует нового аналитического backend.

Цели поля: LCP ≤2.5 s, INP ≤200 ms, CLS ≤0.1 на 75-м перцентиле отдельно для mobile и desktop. Это пороги [Core Web Vitals](https://web.dev/articles/vitals). До публикации полевых данных нет: Lighthouse/DevTools используются для лабораторной проверки LCP/CLS и задержек, но проход Lighthouse не доказывает полевой INP. На staging дополнительно проверять меню и просмотр скриншота через interaction trace; не должно быть повторяющихся длительных задач при скролле.

## 9. Контроль реализации

Разработчик сначала делает полностью читаемые статичные страницы с настоящими ассетами, затем добавляет M01–M06. При споре между читаемостью UI и крупной эффектной подачей приоритет у читаемости. Если анимация недоступна или отключена, текст, картинки, навигация и все целевые действия сохраняются.

Итоговая проверка включает desktop 1440×900, 1920×1080, tablet 768×1024 и mobile 390×844 и 320×568; дополнительно масштаб текста 200%, browser zoom 400% при ширине окна 1280 px, клавиатуру, screen reader, `prefers-reduced-motion`, отключённый JavaScript, медленную сеть и ошибку загрузки отдельной картинки. Критерии по страницам и выпуску находятся в [`06-work-plan-and-acceptance.md`](06-work-plan-and-acceptance.md).
