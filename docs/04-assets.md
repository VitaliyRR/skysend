# Ассеты: что готово и как использовать

Срез источников: 10 сентября 2026 года. Пакет содержит реальные материалы SkySend и созданные кодом SVG-схемы. AI-изображений нет. Изображения DJI не скачивались и не входят в комплект.

Источник истины для файлов: [`data/assets-manifest.json`](../data/assets-manifest.json), табличный вариант: [`data/assets-manifest.csv`](../data/assets-manifest.csv). У каждого скачанного файла есть исходный URL, разделы-источники, размер, SHA-256, назначение и решение о применении. В манифесте 977 записей: 620 проверенных скачиваний, 21 производный SVG, 1 побайтовая копия с правильным расширением и 335 исключённых URL без скачивания. Ошибок получения выбранных материалов нет.

Значения `production_status`:

- `approved-original`: визуал подходит для указанной задачи. Для производных SVG это означает, что они готовы к применению; тип указан отдельно. Статус не подтверждает доступность платежа, наличие товара или свежесть старого интерфейса.

- `reference-only`: помогает восстановить смысл старого сайта, но не является готовым изображением для публикации.
- `excluded`: материал исключён из новой версии.

## Провайдеры: реальные файлы и честное представление

Каталог страницы «Провайдеры» загружает данные из [`providers.php`](https://skysend.ru/providers.php). На дату среза endpoint вернул 600 строк в 13 категориях, из них у 534 есть изображения. Сами картинки выданы публичным HTTP endpoint `cluster.skysend.ru:6721`; в пакет они скачаны локально. Новый сайт не должен обращаться к нему из браузера и создавать mixed content.

В [`data/provider-wall-selection.json`](../data/provider-wall-selection.json) выбраны 16 понятных примеров: МТС, Билайн ТВ, НТВ-Плюс, Триколор, Win Mobile, Сбербанк, Т-Банк, Альфа-Банк, Ozon Банк, WB Банк, VK, Одноклассники, Warface, Xsolla, War Thunder, Аллоды. Точное название конкретной услуги сохраняется в `provider_name`. Например, `provider-6581.png` относится к «Билайн ТВ», его нельзя подписывать как подтверждение любых платежей Билайн.

Большинство изображений имеют размер 150×150; встречаются широкие логотипы 210×33 и 170×103. Подгонять через `object-fit: contain`, не растягивать, не перекрашивать в белый и не делать искусственные объёмные плитки. Для retina целевой размер самого изображения: примерно 60–75 CSS px по длинной стороне; для длинного логотипа учитывать высоту исходника. Контейнеры могут отличаться по ширине, чтобы сохранить оптический баланс.

«Более 5 000 провайдеров и услуг» взято со старого сайта. Число 600 строк публичного каталога не доказывает ни 5 000, ни ошибочность 5 000: объём публичного списка и общее число услуг могут различаться. Правило выпуска и запасной текст заданы в контентной спецификации. Не рисовать 5 000 точек как количественное доказательство. Steam присутствует на старом screenshot, но не найден в текущем снимке endpoint; не добавлять выдуманную строку Steam в данные каталога.

## Что адаптировано, что пересоздано, что оставлено

- Адаптирован логотип SkySend: убраны только поля `viewBox`; версия оригинала сохранена с SHA-256.
- Собрана композиция двух реальных интерфейсов: изменена подача, а не содержимое экранов.
- Созданы простые SVG-схемы оплаты, XML, заказа товара, поддержки, POS и FINGER. Ноды обозначают конкретные участники и действия из текстов сайта. Схемы не притворяются продуктовым интерфейсом.
- Созданы 8 иконок: `terminal`, `phone`, `desktop`, `xml`, `document`, `arrow-right`, `menu`, `close`. Размер 24×24, линия 1,75, `currentColor`. Иконка внутри кнопки декоративная; доступное имя задаётся самой кнопке.
- Сохранены 22 исходных изображения оборудования. Новый студийный снимок можно заменить в тех же рамках, но макеты и разработка не зависят от фотосессии.
- Все баннеры акций, финансовых предложений, «подарков», рекламы и общие стоковые фотографии исключены из визуального языка нового сайта. Они присутствуют только в архивных доказательствах аудита.

## Выходные размеры и вес

SVG-схемы сделаны с Inter/Arial и фиксированным `viewBox`. Для `<img>` задавать `width` и `height`; для отзывчивой ширины использовать `width: 100%; height: auto`. Не уменьшать горизонтальную схему до нечитаемой картинки на телефоне. Для заказа уже есть отдельный мобильный вариант; для остальных схем на узком экране переверстать те же узлы в HTML вертикально и сохранить текстовую последовательность.

Изображения оборудования держать отдельными от текста. Во вторичных блоках целевая видимая высота терминала 360–420 CSS px на desktop, 280–340 CSS px на mobile. Для hero отдельный контракт: 510 px на desktop и до 360 px на mobile; исходник в этом размере не обеспечивает полные 2×, это принятый предел качества. RMA Android: 154 CSS px рекомендовано для 2×, допустимый максимум 260 CSS px без обещания полной резкости 2×. Сильно увеличенные детали товара из маленького PNG запрещены. Не использовать AI-upscale, который дорисует щели, разъёмы или текст на корпусе.

Для экспортов продукта и скриншотов: `320 / 640 / 960 / 1440` по реальной потребности и только до доступного разрешения. Прозрачные предметы сохранять с alpha. Перед экспортом screenshot убедиться, что тонкий текст читается; AVIF не использовать ценой размытия цифр. Оригиналы держать вне директории `public`; копировать только выбранные варианты.

Ориентиры: LCP-изображение до 220 КБ; изображение терминала 50–160 КБ; первый набор логотипов суммарно до 160 КБ; каждая схема без raster embedding обычно до 8 КБ. Это бюджеты реализации, не заявление о текущем весе оригиналов. `interface-customization.svg` служит мастер-файлом и требует оптимизированного экспорта для сайта. Только LCP получает preload; остальные иллюстрации lazy. Все размеры и варианты указывать явно, чтобы не было сдвигов layout.

## Шрифт и права на материалы

`assets/fonts/InterVariable.woff2` получен из [официального проекта Inter](https://rsms.me/inter/), файл весит 352 240 байт, диапазон веса 100–900, стиль normal. Лицензия [SIL OFL 1.1](https://github.com/rsms/inter/blob/master/LICENSE.txt) сохранена в `assets/fonts/OFL.txt`. Для основного текста веса 400/500, заголовков 600/700; не использовать сверхтонкие начертания. Fallback: Arial, sans-serif. Связанный CSS описан во фронтенд-спецификации.

Изображения SkySend и сторонние торговые знаки получены с указанного пользователем сайта для его редизайна. Их нельзя объявлять свободной стоковой библиотекой. Внешность логотипов сохраняется; наличие картинки в каталоге не означает новое соглашение с соответствующим брендом. При замене текущей фирменной версии использовать официальный файл владельца бренда и обновить provenance в манифесте.

## Проверка и воспроизведение

Проверены форматы и размеры всех выбранных raster-файлов; все 534 provider-logo декодируются как PNG. Каждый скачанный материал снабжён SHA-256. В `actual_mime` записан формат по содержимому файла. Единственный найденный mismatch: `pop-up-full.jpg` фактически PNG. Для публикации создан `assets/ready/terminal-screen.png` с теми же байтами и SHA-256; встраивать его как `image/png`. Для data URI никогда не определять MIME только по расширению. SVG проходят XML-разбор. Визуально проверены контактные листы оборудования, выбранных провайдеров, ПО и все новые схемы, включая мобильную схему. Контактные листы полного каталога позволяют просмотреть все 534 логотипа, но не заменяют проверку актуальности услуги.

Скрипты:

1. `python tools/collect_assets.py`: извлечение изображений из сохранённого HTML и получение исходников. Нужны `requests`, `beautifulsoup4`, `Pillow`.
2. `python tools/build_vector_assets.py`: генерация схем, иконок, адаптации логотипа и композиции реальных экранов. Только стандартная библиотека Python.
3. `python tools/finalize_assets.py`: объединённый манифест, статусы, SHA-256, CSV.
4. `python tools/build_contact_sheets.py`: контактные листы, требуется Pillow. Скрипт меняет только QA-изображения, не исходники.
5. `node tools/render_vector_assets.cjs`: PNG-превью SVG через Sharp. Путь к установленному Sharp в скрипте относится к текущему runtime и на другом компьютере заменяется на обычный `require('sharp')`.

При повторном скачивании источник может измениться. Не заменять контент в production автоматически: сверять новые размеры, hash, текст на изображении и состав каталога. Для схем достаточно статичного состояния; порядок и смысл не должны зависеть от проигрывания анимации.

## Предметные иллюстрации партнёров

В отмеченных пользователем разделах предметные сцены заменены функциональными HTML-композициями из [workflow-visuals.json](../data/workflow-visuals.json): управление, каналы оплаты, обмен каталогом, распределение платежей и запуск точек. Подписи относятся к действиям из текста, стрелки обозначают направление передачи. Фотографии терминала, экран РМА и знаки FINGER/SkyMarket остаются оригинальными. Композиции не имитируют интерфейс кабинета. Ранее созданные предметные иллюстрации сохраняются для плиток главной и остальных утверждённых разделов.
