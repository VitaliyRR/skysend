# Новая структура SkySend

Дата фиксации: 10 сентября 2026 года. Это комплект для проектирования и реализации публичного сайта. Личный кабинет и платёжное ПО показываются как существующие продукты; их интерфейсы не проектируются заново в рамках этой работы.

## Решение

Главная объясняет систему через терминал, каталог провайдеров, реальные экраны ПО и рабочие сценарии. Внутренние страницы отвечают на вопросы конкретной аудитории. Коммерческие предложения с ограниченным сроком, скидки, акции, рекламные вставки и автопробег отсутствуют. Раздел рекламных услуг также исключён из активной структуры в рамках широкого трактования запрета на промо. Источники этих материалов сохраняются только в исследовательском архиве.

Основная навигация: **Партнёрам · ПО · Оборудование · Провайдеры · Поддержка**. Справа: **Войти**, кнопка **Подключиться**. Логотип ведёт на `/`. Загрузки доступны внутри «ПО», с каждой страницы продукта и в футере. «О системе» и «Контакты» доступны в футере и меню мобильной версии. Максимум два уровня меню.

## Главная, порядок блоков

| ID | Содержание | Что подтверждает изображение | Действие |
|---|---|---|---|
| hero | Система приёма платежей SkySend | Реальный терминал Beauty, его экран и оборудование для приёма платежей | Подключиться; Посмотреть ПО |
| providers | Более 5 000 провайдеров услуг | Иконки конкретных провайдеров из старого сайта | Провайдеры услуг |
| terminal-software | Терминальное ПО | Реальный экран выбора услуги/ввода номера | Подробнее о терминальном ПО |
| customization | Изменение цветов и фона | Реальные варианты интерфейса из одной исходной иллюстрации | Возможности интерфейса |
| commerce | Продажа товаров и услуг | Последовательность «справочник → заказ → оплата» из старого описания | Поставщикам товаров |
| partners | Партнёрам | Шесть предметных маршрутов с устройством или схемой для каждого | Страница выбранной аудитории |
| equipment | Платёжные терминалы | Beauty и FastPay Simple в сопоставимом масштабе | Оборудование |
| support | Круглосуточная поддержка | Реальные телефон и Telegram как функциональные контактные элементы | Поддержка |

Короткая подпись возле архивных экранов: «Интерфейс ПО SkySend». При просмотре в увеличении: «Экран из материалов действующего сайта. Внешний вид зависит от версии и настроек ПО». Не обозначать архивную графику как новую версию продукта. Число 5 000 сохраняется из исходника, а не из нового пересчёта каталога.

## Сведение старых страниц

Подробная построчная таблица находится в `data/migration-map.csv`. Маленькие страницы преимуществ внутри каждой аудитории становятся адресуемыми секциями. Якорь равен последнему старому slug: например `remote-control.html` → `/partners/agents/#remote-control`. Раздел `/benefits.html` ведёт на `/partners/`, дочерние преимущества на соответствующий смысловой раздел. Точные назначения определены CSV, а не угадываются разработчиком.

При переносе сохранять полную полезную информацию внутри секций. Не заменять статьи одинаковыми карточками с одним предложением. Длинные инструкции отображать как последовательность действий; дополнительные детали открывать в доступном disclosure. Ключевой смысл и ссылки видны без раскрытия.

Исключённые промо URL возвращают 410. Страница 410: «Материал больше не доступен»; текст «Перейдите к информации о системе SkySend.»; ссылки «На главную» и «Поддержка». Не перенаправлять все удалённые материалы на главную. Не добавлять их в меню, sitemap и внутренний поиск.

## Действия без неопределённого backend

Вход и регистрация остаются внешними действиями по ссылкам старого сайта. Не создавать собственную форму пароля. Сначала использовать `/connect/` с понятным выбором пути. На карточке оборудования действие «Обсудить оборудование» ведёт на контакты, где уже есть телефон и email. Не рисовать корзину, наличие, оплату и «Заявка отправлена», пока такого сервиса нет.

На странице провайдеров используется локальный снимок из `data/providers-source.json`: 600 записей и 13 категорий. Поиск и фильтры работают по этому массиву; рядом указана дата снимка. Не изображать наличие полной базы из 5 000 записей. Готовые подписи и состояния находятся в `docs/07-developer-handoff.md`. Обновление снимка не меняет дизайн и контракт поиска.

## Правила мобильной структуры

Меню открывается кнопкой «Меню», занимает отдельную непрозрачную область. Сначала пять основных пунктов, затем «Скачать», «О системе», «Контакты», действия входа и подключения. Группы раскрываются кликом; hover не требуется.

Hero: сначала текст и действия, затем терминал. Провайдеры: компактная сетка, никаких бегущих логотипов. ПО: одна читаемая картинка, с увеличением по нажатию. Схемы перестраиваются вертикально. Галерея позволяет ручное переключение с подписью кадра. Футер содержит контактные данные сразу, без обязательного раскрытия.
