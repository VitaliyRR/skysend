SVG содержат изображения и шрифт внутри файла. Их можно открыть в браузере или импортировать в редактор, поддерживающий SVG. Текст, фигуры и размещение объектов доступны для редактирования. Обязательность параметров задаёт спецификация, а не результат автоматического импорта в конкретный редактор.

Это композиционные макеты с реальными ассетами. Ссылки и кнопки нарисованы для передачи внешнего вида и не работают как сайт. В PNG используется шрифт, доступный SVG-рендереру; браузерная версия SVG содержит локальный Inter. В рабочей вёрстке используется Inter из комплекта. Полные тексты, которые могут быть длиннее фрагментов на композиционной доске, находятся в `data/site-content.json` и `data/secondary-content.json`.

Макеты задают один вариант оформления, а не набор альтернатив на выбор. В desktop используется реальный терминал и экран ПО, затем логотипы каталога, настройка, процесс заказа, аудитории и контакты. Mobile показывает перестроение в один столбец. XML демонстрирует подход к странице, где изображением служит предметная схема обмена.

Обязательные правила:

- Внешний вид старого ПО сохраняется только внутри его изображения. Сайт не наследует старые градиенты, объемные кнопки и тени.
- `interface-customization.svg` показывает только два верхних кадра исходника. Не открывать нижние кадры с промо даже в lightbox.
- Исходные изображения оборудования имеют ограниченное разрешение. Не увеличивать их произвольно. Параметры размеров и альтернативы перечислены в реестре.
- Любые цифры, цены, названия сервисов внутри архивных экранов не являются отдельным текущим предложением нового сайта.
- Картинка товара не должна использоваться для другого продукта. Для POS, у которого нет фотографии в источнике, предусмотрена условная иконка устройства с подписью, а не подставная модель.

Сборка: `python tools/build_design_boards.py`; рендер: `node tools/render_design.cjs` при доступном пакете `sharp`. Файлы PNG уже входят в комплект, повторять сборку для начала разработки не требуется.
